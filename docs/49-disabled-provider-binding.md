# 49 — Disabled ScienceDirect request and parser binding (EM-015d)

Status: local candidate, partial EM-015. These are reusable production prerequisites tested with supplied synthetic bytes. Live acquisition, provider admission, credential resolution, source certification and production execution remain unimplemented. No source policy, schema, migration, dependency, API/UI registration or permission changes.

## Canonical request and response boundary

`fetching/sciencedirect.py` accepts exactly one typed `SearchRequest` or normalized `ArticleIdentifier`. It rebuilds the existing PUT search or GET XML plan, with fixed `https://api.elsevier.com` origin, canonical route, supported media and exact request bytes. It never consumes an arbitrary `RequestPlan`, headers, URL, proxy or credential value. The request fingerprint covers method, full canonical URL, media type and body digest; different queries at the same search URL therefore have different fingerprints. Existing `execution_enabled=False` remains descriptive, not an authorization check.

`ProviderBinding` is a server-owned comparison value containing organization, job, item, lease token, execution/deletion generations, policy version/revision, discovery revision, purpose, source, request fingerprint, bounded monotonic deadline and an opaque tenant-scoped credential reference/revision. It contains no key, secret-manager URI, credential resolver or header values. Its source and credential origin are fixed. This is an internal contract, not an API body or newly approvable policy. Constructing it does not grant any rights.

`ProviderBoundary` reuses `HopPlanner`: exact origin/path authorization, current scope checks, deadline checks, public DNS snapshot/peer validation hooks and zero redirects. The future protected transport must use those hooks and obtain actual socket/TLS/DNS evidence. The existing protected socket gateway is still its unchanged synthetic GET/HTML acceptance implementation, not a provider transport. DOI punctuation that produces percent-encoded paths remains refused by the shared gateway's existing narrow URL rules; the identifier parser's wider subset is not silently a transport capability.

The supplied `current()` callback must resolve current server authorization, membership/session, purpose, entitlement/quota, source policy, credential scope, lease and deletion/discovery state each time. It must never return a client-supplied or cached binding as authorization. The default callback always refuses. Controlled tests use explicit comparison values to exercise stale-field refusal, not to prove real-source database admission. No current database/source policy can authorize the provider; existing policy accepts only the synthetic host and null credentials.

The response's dispatch binding must be attached by the trusted transport from the exact request it executed, independently of publisher headers/body. Before consuming bytes, the reader compares that complete binding and exact effective URL with its own expected values. This rejects same-URL query, tenant, job and lease swaps. Returned fields are not evidence that a protected request happened. There is no HTTP parser, live dispatch or way to turn on acquisition; `acquire_live` always refuses.

## Stream and release controls

Only status 200 and the closed expected JSON/XML media set are accepted. Every redirect, 401/403/429, HTML challenge and compression response fails without retry, credential forwarding, identity change or fallback. All redirects are refused, including same-origin redirects; search PUT bodies cannot silently become GET requests or be replayed elsewhere.

Search bodies are capped at 1 MiB and XML bodies at 2 MiB; at most 4096 chunks are accepted. Empty streams, non-byte chunks, oversized bodies, invalid/mismatched declared lengths and iterator errors refuse. Authority and the shared 60-second maximum deadline are checked before and after each iterator step and before releasing bytes. Errors expose fixed reasons, not stream exceptions or payload text. The actual transport must additionally impose a deadline on each blocking read, cap its own incoming chunks, reject ambiguous/duplicate HTTP framing and close the stream on every path. These pure checks cannot interrupt a blocking iterator or establish enforced network egress.

The resulting in-memory `AcquiredResponse` holds the canonical request, exact dispatch binding, exact bounded bytes and SHA-256. Search parsing consumes that object, rechecks scope, and returns the existing explicit metadata-only `SearchPage`. Generalized XML parsing consumes the same object and rechecks authority before and after its isolated child. No result is automatically persisted, accepted as an identity, exported or sent.

## Generalized isolated XML protocol

The existing fixed worker command now receives `xml-input-v1`: one canonical ASCII JSON line of at most 1024 bytes, followed by at most 2 MiB raw UTF-8 XML bytes. The header contains only protocol version, normalized requested identifier, expected content digest and one declared supported XML profile. No URL, tenant, policy, lease, credentials, command or environment override enters the child. Duplicate/unknown fields, malformed/noncanonical headers, nonfinite numbers, missing framing and digest/size mismatches refuse. Raw bytes avoid base64 expansion and preserve the exact input digest.

The child validates the frame only after its unchanged kernel isolation checks, parses with the existing bounded XML parser, then checks identifier/digest/profile against its input expectation. The host independently retains its expectation and compares the output with that and its actual acquired bytes. A parser cannot replace the server's acquisition URL or authority. `BoundXmlObservation` keeps the original acquisition alongside raw observations; these are not retained contacts or a persistence permission.

`parse_isolated` remains explicit-test-mode only. Existing synthetic callers still use the fixed synthetic identifier/digest/profile by default, and now travel through the same framed protocol. Its immutable local image verification, fixed command, network-none/nonroot/read-only/resource profile, bounded concurrent pipes, 30-second child deadline, sanitized errors and owned-container cleanup remain unchanged. The extra header does not raise the XML byte cap, output cap or sandbox limits. Rebuild the diagnostic image before running the new host channel; an old unframed worker is incompatible and fails closed.

`RetainedXml`, `XmlExtraction`, source policy, SQL/migration 0012 and association/export gates remain exact to the original synthetic fixture. A different identifier/body can be parsed in the isolated test channel but cannot pass those persistence guards. Existing same-container→database→review→CSV/XLSX acceptance remains mandatory. The native XOCS profile and unverified Article Retrieval wrapper assumption retain their previous limitations; the framed protocol does not certify a real response or establish access rights.

## Verification and rollback

Run the focused and aggregate commands recorded in [EM-015d evidence](../reports/em015d-validation.md). `test_provider_boundary.py` covers canonical request integrity, same-URL dispatch swaps, every binding field, stream/media/status/byte/time refusals, protocol framing, a second synthetic DOI/native PII profile and unchanged source/persistence refusal. Three actual-container cases require `EM_REQUIRE_XML_ISOLATION=true` and the built image; local skips are not passing isolation proof. `parser_acceptance.py` also exercises the generalized input protocol inside its unchanged actual network-none/resource diagnostic.

No migration or deployed service changes. Rollback reverts these source/test changes and rebuilds the matching diagnostic image; no durable data is changed. All seven own-head CI gates and independent immutable-tree review remain required. Full EM-015/016 still need verified organizational source authorization/entitlement, approved actual response samples, a reviewed real protected acquisition/admission/secret-reference implementation, bounded pilot and held-out benchmark. No assumption is made about whether the organization already holds rights or credentials.

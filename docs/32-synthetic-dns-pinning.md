# 32 — Synthetic DNS snapshot and immutable TLS pinning

EM-004d is a bounded test-only follow-on to verified Draft PR #7 head 3d640132/tree 5e0eef23. It adds actual disposable loopback UDP DNS-wire validation before the existing immutable loopback TLS connection, including existing tenant policy and browser mediation. Full EM-004 remains PARTIAL and EM-006 gated: this is not public-DNS, approved-domain firewall or production egress certification. No live source, new dependency, infrastructure, security setting, migration or persistent access is introduced.

## Boundary

The frozen SyntheticDNSRoute admits only synthetic.publisher.example at a literal 127.0.0.1 DNS server port selected by trusted test composition. Explicit test environment and fixture mode are mandatory; default/production construction fails. DNS responses never select the TCP destination: TLS always dials its separately frozen SyntheticEndpoint literal 127.0.0.1, with actual peer, CA, SNI and hostname verification. Public-address safety classification remains unchanged and rejects loopback for public routes. The only loopback exception is this explicitly separate test composition; browser IPC cannot supply a resolver, endpoint, CA, socket or credential.

Each authorized request hop resolves A and AAAA through connected loopback-bound UDP sockets with fresh transaction IDs and source ports, one send/receive and no cache/retry/system-resolver fallback. Both questions and TLS share the existing absolute deadline. Complete replies are bounded 512 bytes and require matching ID/question, exact selected flags/counts, fixed owner/type/class/length, bounded TTL and complete consumption. Only the full fixed owner or its exact pointer to the already validated question is supported; no general compression, CNAME/DNAME or extra record processing is provided. Empty AAAA requires one fixed zero-negative-TTL SOA authority record. A must be exactly 127.0.0.1 and AAAA empty; mixed, duplicate, alternate or IPv6 answers fail closed.

The resolver is deliberately a constrained DNS-wire fixture, not a general DNS implementation. Standards basis: [RFC1035 wire format/compression](https://www.rfc-editor.org/rfc/rfc1035), [RFC5452 query/response matching](https://www.rfc-editor.org/rfc/rfc5452), [RFC3596 AAAA format](https://www.rfc-editor.org/rfc/rfc3596), [RFC2308 negative-answer authority](https://www.rfc-editor.org/rfc/rfc2308). No compliance claim beyond the declared grammar follows.

Tenant authorization occurs before DNS, again after DNS/before TCP, on every redirected hop and before releasing bytes. DNS mutation therefore cannot grant another target, and permission revoked while DNS blocks cannot permit a TCP request. Existing browser mediator delegates to the same exact TLS gateway; its container/profile/IPC controls remain unchanged. Host browser CI records DNS query counts agreeing with its approved gateway receipts; the browser still has no network access.

## Checks and remaining acceptance

Ordinary tests use owned disposable loopback DNS/TLS servers. They cover no OS name service, changing answers across requests and redirects, mixed/unlisted/IPv6 records, wrong owned UDP source port, missing/oversized/malformed replies, framing/pointer/authority rules, shared deadline, authorization before/after DNS, no TLS fallback and explicit production refusal. A real PostgreSQL/API test additionally checks browser-operation policy, another tenant and current revocation without additional DNS/TLS receipts. The separate actual browser job must still pass all existing sandbox/subresource/worker/popup/download/credential checks while recording the host DNS gate; no simulated test substitutes for that job.

Run scripts/check.sh for aggregate gates and the existing synthetic browser/parser workflows for actual isolation evidence. Unavailable local PostgreSQL/broker tests must be disclosed as skips; fresh independent exact-tree review and actual no-skip CI are mandatory before the slice is verified. See [validation](../reports/em004d-validation.md).

Generalized public-DNS/rebinding/connection-time approved-domain HTTP/browser egress and production configuration still require a separately bounded implementation and actual evidence; EM-006 must not start from this partial slice alone.

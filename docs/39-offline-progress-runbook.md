# 39 — Synthetic execution, resumability and authorized progress

## Scope and authority

EM-010 advances registered synthetic extraction jobs through their real PostgreSQL lifecycle. It reuses current tenant/session/source permissions, retained discovery, HTML/browser observations and association receipts. No source acquisition is enabled outside the explicitly selected fixture assembly. The UI remains a scaffold; these are UX-facing APIs, not a completed user interface. Production execution remains unavailable.

Migration 0007 is forward-only. Runtime can SELECT the five new forced-RLS execution tables, but cannot INSERT/UPDATE/DELETE them. Fixed-search-path owner functions implement bounded start, claim, finish, control, reconciliation and continuation operations. No catalog UPDATE or authentication/bootstrap privilege is added. Existing tenant context remains the authority; transaction-local work identifiers are server-owned, never request headers.

## Durable lifecycle and checkpoints

Start checks expected job revision, current approved source version/purpose/operations, deletion epoch and actual discovery plan. It atomically creates a run/frontier/identifier-only outbox, then moves draft through ready to queued. The first current lease moves queued to running. Work identities are stable within job/kind/registered URL; current event, nonce, generation, deletion epoch and expiry fence publication and effects. Source/item bounds remain the six registered search/article URLs, three attempts per work unit and at most 120 seconds per lease.

Discovery work commits real page checkpoints and reconstructs successors/frontier from PostgreSQL. Article work retains a real observation, derives its actual association batch, then commits one root-lineage effect. A crash between these stages reuses existing immutable observations/batches. It does not claim a single transaction across source parsing. A static requires_browser observation is an explicit unsupported/browser_not_completed gap. It never invents a browser result. The controlled synthetic browser test separately completes the claimed tooltip item from actual isolated DOM evidence under the same unchanged sandbox/network restrictions.

Pause increments generation, clears active leases, preserves permitted observations and immutable checkpoint facts, and settles an exhausted final attempt rather than orphaning it. Resume reauthorizes and rebases only the checkpoint generation/revision; retained source provenance is unchanged. Already committed page work keeps its original commit threshold. Cancel clears remaining work and prevents new effects while leaving currently permitted retained results readable. Terminal jobs cannot be reopened.

Retry creates an audited new continuation for exhausted transient article or current-page failures. Original terminal state is immutable; one continuation per predecessor makes repeat retry requests idempotent. The continuation retains root identity/current policy/deletion/retention ceiling and selects failed URLs only. Successful effects, unsupported browser/access/policy blocks and user cancellation are not silently retried. A failed current page resumes from its immutable checkpoint; prior terminal article receipts are inherited through same-tenant item/batch references and are never reacquired or inserted as new effects. Items disclose their inherited job/item identifiers. This bounded fixture behavior does not claim a universal retry connector or commercial quota implementation.

The test assembly reuses jobs.broker.create_worker with the existing disposable FixtureWorkerConfig; construct Progress from that worker ledger database/session/settings and call progress.broker.publish for its configured organization. Repeated confirmed publication and explicit reconciliation are trusted test orchestration, not an enabled production scheduler. The existing JSON-only confirmed quorum broker uses IDs/generation only. Publication is marked only after broker confirmation; late acknowledgement and worker-loss rejection preserve original-message recovery. Reconciliation clears expired leases, bounds attempt exhaustion and reopens current-generation unleased pending/retry publication after an uncertain or lost broker delivery. Active leases and terminal items remain untouched; repeated publication is safe. A queue message or SSE frame is never completion authority.

## Counters and metadata replay

GET progress reports actual job revision/generation, unique durable frontier, pages/duplicates, quality counts and per-outcome processing counts. Missing scheduled rows count as pending while execution is active. Cancellation first materializes the durable checkpoint frontier and terminalizes every remaining unit atomically; terminal reconciliation performs no reconstruction or mutation, including after source revocation. Unknown or capped enumeration reports progress_percent null; a publisher-reported total is informational only. Processing completion, accepted correspondence, technical validation and outreach eligibility remain distinct. All-no-contact and needs-review can finish; access/policy/unsupported/failed/capped gaps produce completed_partial. A positive empty exhausted frontier can complete.

GET progress/items returns at most 100 metadata records (the fixture frontier is at most six units) with bounded IDs, work kind, state/reason, attempt count, association batch ID and completion time. It excludes URLs, raw emails/evidence, lease tokens, credentials and source bodies. The existing legacy probe items endpoint remains separate.

An immutable per-job journal orders metadata events. Review inserts update the association, its audit/history/outbox and every currently readable same-tenant execution journal referencing that batch in the same transaction, including continuations inheriting the receipt. Review events contain only batch/association identifiers and revision; corrected addresses/reasons/evidence stay in their separately authorized retained records. No broker-delivered review event is claimed.

GET events authenticates before HTTP 200, then rechecks current server tenant/session/source authority before every replay frame or heartbeat. Last-Event-ID is exactly organization UUID/job UUID:sequence; other tenants/jobs, noncanonical or future cursors refuse. Streams are bounded to 60 seconds/100 events and reconnect from durable sequence, with no-store headers. Cancellation/expiry closes the stream without cached frames. Timed-out database reads may finish inside their already bounded connection transaction, but their results are never emitted later. SSE cannot express mailbox/outreach probabilities.

JSON Schemas enforce structural metadata shape and review identifier parity. Runtime additionally enforces counter conservation, truthful percentages, timezone-aware timestamps and relational tenant/source semantics; validate model objects as well as schema.

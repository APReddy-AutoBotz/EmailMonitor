# Transient review context

FR-020's additional-source workflow is not yet a durable attachment or a way to accept a mapping using another observation. As a narrower starting capability, a reviewer can request one retained citation from a different batch as temporary context for a current association. The selected source is not asserted to describe the same person, and neither review decision, author identity, association revision, local evidence membership nor export changes. A matching name, address or DOI does not prove identity. This view cannot be used as a citation in the existing review endpoint.

The UI shows source batch and evidence identifiers for current-authorized citations. The reviewer may enter those identifiers for another observation, and the server rechecks the target revision and both current-authorized batches in one transaction using the existing review capability, RLS and parent fences. It acquires the two batch locks in a deterministic order and re-reads both before release. The UI discards delayed responses when the selection changes, clears on refresh/unmount and fails closed on a mismatched response. The response is a point-in-time view; refresh is needed to recheck later revocation or expiry.

Each successful read writes two fixed-action audit entries, identifying the actor and the separately viewed target association and source evidence. These contain no citation text, name or address. Existing audit retention applies; the two entries do not constitute a durable cross-observation reference or a review decision. An audit-write failure aborts the transaction and response. The endpoint creates no attachment, copied source evidence, new foreign key, automatic identity relationship or durable context row; source or target deletion cannot be blocked by such a row. Existing review, audit, privacy and export controls remain unchanged.

The service is restricted to human reviewer-capability sessions and the existing fixture environment. It adds no source or operation authorization, grants, migration, live collection or network access. Disposable PostgreSQL tests exercised both tenant directions, viewer refusal and reviewer access, two audit entries and atomic audit failure, independent review and unchanged XLSX export, source policy revocation, source deletion and purge, and the source-deletion and reviewer-membership lock orderings. These are synthetic tests of the stated cases, not proof of every interleaving or an installed deployment. A separate existing RabbitMQ discovery restart/redelivery test passed; the temporary context endpoint does not use a broker. The installed-browser journey exercises the context and actual audit entries but remains pending until its hosted run completes. Durable contextual references and evidence-backed cross-observation correction require a separate lifecycle/identity contract, audited attach and unlink, and current-source/export checks; this temporary view does not implement them.

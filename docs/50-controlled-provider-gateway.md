# 50 — Controlled ScienceDirect provider gateway (EM-015e)

Status: local candidate, partial EM-015. This slice makes canonical provider requests executable through the existing protected gateway in its explicit controlled test composition. It does not activate a source, implement live database admission, resolve a real credential, contact a publisher or certify production acquisition. Exact-tree review and all seven own-head CI gates are required; [validation](../reports/em015e-validation.md) distinguishes local checks from actual HTTPS/container evidence.

## Exact native request semantics

Official [ScienceDirect V2 Search WADL](https://dev.elsevier.com/documentation/ScienceDirectSearchAPI.wadl) specifies native PUT `/content/search/sciencedirect`, JSON request/response and X-ELS-APIKey. The existing `qs`/`display` JSON body is unchanged and preserves the original query, offset, page size and sort. POST is not silently substituted. Official [Article Retrieval WADL](https://dev.elsevier.com/documentation/ArticleRetrievalAPI.wadl) specifies GET DOI/PII routes and text/xml. This slice retains the existing no-query canonical article route; its default META view and source entitlement mean a successful synthetic full-text-shaped response does not prove real full-text access. API keys alone do not establish rights.

Only revalidated `ProviderRequest` search/article inputs enter `ProtectedGateway.acquire_provider`. The fixed API origin, method, route, media and exact body come from that type, never an arbitrary RequestPlan, URL, header map or HTTP response. Revalidation also rejects forged model copies before credential access or DNS. Percent-encoded DOI paths remain unsupported by the shared URL classifier.

## Shared executable transport

HTML and provider dispatch share the same private literal TCP/TLS connection, strict HTTP headers and bounded reads. No connector-level socket implementation or new network exception exists. The resolver still queries both A/AAAA families on its closed configured literal route; all addresses must pass the existing public-address classifier. One selected literal is connected on port 443 without OS lookup, proxy inheritance, alternate address or retry. Actual peers are checked before and after TLS, with original-host SNI, CA verification and hostname verification required.

Each provider blocking read has the same absolute bounded deadline and full current-binding checks before and after. Legacy HTML preserves its original deadline-only read checks and current-authority check before final release. Headers are capped at 8192 bytes; duplicate/ambiguous headers, transfer encoding, unsupported status/media/compression, short bodies, surplus bytes and a peer that does not close before the deadline refuse. A bounded header read can already contain initial body bytes, but no response is released before all checks. Provider search bodies remain capped at 1 MiB and XML at 2 MiB; the existing smaller transport limit can further restrict these. All redirects, 401/403/429 and challenges terminate without forwarding credentials, method changes, identity substitution or retry.

The trusted dispatch itself attaches the exact request/binding to acquired bytes; publisher headers cannot supply authority. Authority is checked after resource admission, credential resolution, DNS/TLS latency, reads, resource completion and parsing. A resource ticket is finished once on every owned exit; actual status and bounded Retry-After are available even when a status/body is rejected. Sockets and credential contexts close on failure/cancellation, and errors use fixed reasons. This is not a remote credential erasure guarantee: Python immutable bytes cannot promise memory zeroization.

## Opaque credential and admission interfaces

`CredentialResolver.open` receives only an opaque tenant/source/origin/reference/revision and exact request fingerprint. Its context returns a short-lived `CredentialLease`; the gateway checks that exact scope and a bounded restricted ASCII value before emitting only X-ELS-APIKey to the fixed origin. There is no environment lookup, provider token URI, caller header map, cookie jar, institution token, real secret-store implementation or saved credential. The default resolver refuses before DNS/TCP. Secret material is excluded from request/response contracts, repr, owned-pipe messages, parser frames and fixture receipts. The controlled guest has only one fixed fake fixture value.

The `current()` implementation must eventually resolve actual server membership/session, tenant state, source entitlement/purpose/quota, policy, credential revision, execution lease and deletion/discovery state. A binding remains a comparison value, never a permission grant. Current source policy still refuses provider hosts and non-null credentials; synthetic SQL grants are not repurposed to authorize Elsevier. No provider API/UI or worker registration exists. `acquire_live` and production configuration remain refused.

## Controlled actual acceptance

The existing isolated dual-stack topology gains only a closed api.elsevier.com DNS question, ephemeral fixture certificate SAN and fixed synthetic PUT/GET routes. Those names resolve exclusively to the already-owned fixture endpoints inside the internal isolated bridge. IPAM, routes, forwarding preparation, sandbox profiles, resource bounds, capabilities, mounts, DNS upstreams, baseline/ownership and cleanup checks are unchanged. No actual Elsevier DNS or HTTP request is made.

The owned pipe's existing 8 KiB input / 64 KiB output / 512 KiB cumulative caps remain unchanged. Provider callback/result messages are a small-fixture diagnostic protocol, not a production 2 MiB byte channel. Host callbacks compare the full original request/binding and exact scope; they are controlled test state and do not claim real-source SQL authorization. Protocol mismatch or uncertain completion poisons the channel without retry or reset. Receipts redact the fake header value.

The transport workflow builds the existing parser diagnostic image before protected preparation, using the unchanged Dockerfile/profile. Provider cases run in a second sequential module-scoped instance of the exact existing owned topology, after legacy cleanup. This preserves the128-command fixture lifetime cap, the legacy held-response 50-snapshot allowance, 32-frame legacy callback budget and cumulative pipe bounds without broadening them. Required controlled acceptance grows from 14 to 31 cases: exact query PUT and GET XML→actual network-none parser on IPv4/IPv6; DNS/TLS refusal before HTTP; zero-retry redirects/status/challenges; duplicate/short/extra/large framing; and lease/policy/deletion changes after actual response before byte release. Existing actual tenant SQL/browser/admission/deletion cases remain mandatory. Pure local protocol/socket-simulation checks and test collection are not actual HTTPS/isolation evidence.

## Remaining activation blockers and rollback

Still unimplemented/unverified: real-source tenant admission and entitlements; real secret-store integration; a reviewed usable live DNS/egress composition (the existing authoritative resolver rejects recursion/CNAME and long TTLs); provider route/API/worker registration; authorized response samples, full-text view/entitlement and wrapper compatibility; bounded pilot and held-out benchmark. Fixed synthetic persistence/review/export restrictions remain unchanged. This slice therefore does not make credentials the only remaining blocker.

No migration, schema, dependency/license, source grant, live setting, production packaging, merge or deployment changes. Rollback reverts this source/test slice and rebuilds the matching diagnostics; no durable data is changed. The next step is reconcile immutable review and actual own-head 31-case controlled/all-seven gates, then implement separately scoped remaining activation prerequisites without fabricating permissions or requesting broad security changes.

## Reproduced mechanism and bounded correction

Pinned Celery 5.6.3/Kombu 5.6.2/amqp 5.4.1 use a snapshot of the hub ready set. Kombu's actual scheduled pyamqp reader can synchronously dispatch the actual registered task through Celery's handler/strategy/solo pool while that snapshot is running. Celery marks its Request acknowledged and queues the original message ACK promise through `Consumer.call_soon`; the new promise misses the current snapshot. With the existing heartbeat 120/checkrate 3 and timer max interval 10, the hub then requests a 10-second poll. A no-network probe measured baseline 10.012541 seconds versus a coalesced-pipe wake 0.003873 seconds, both with requested timeout 10.0, pending callbacks 2, task_postrun 1 and channel ACK 0 at first poll. The next normal iteration sends the original ACK exactly once. These timings prove the constructed mechanism, not the precise path of the failed CI run.

The runtime delta is a consumer bootstep registered only in the explicit test fixture worker factory and included only for the exact solo TaskPool with an asynchronous hub. It allocates exactly two nonblocking close-on-exec pipe descriptors. Its existing-hub `on_tick` callback reads only the pinned private `_ready` set under `_ready_lock`; when nonempty, one coalesced byte makes the existing poll readable. Its reader drains that byte. It does not inspect task content, run callbacks, replace promises or change their ordering. This is same-event-loop-thread scheduling only, not a cross-thread wake guarantee.

Start is idempotent per hub. Stop/shutdown/terminate safely removes reader/hooks and closes both owned descriptors. Hub.close/reset first clears readers/closes its poller and directly iterates close hooks, so the adapter's separate close hook closes descriptors and removes only its tick hook. One inert close hook remains until explicit cleanup/reinstallation; it cannot recreate the closed poller. Reconnect removes that hook before allocating a fresh pair. Errors clean up and propagate; an uncertain descriptor close is not retried. The exact two private ready fields are pinned compatibility obligations and tested with the installed dependency versions.

Files changed: `jobs/callback_wake.py`, fixture factory `jobs/broker.py`, `test_worker_callback_wake.py`, runbook 41, traceability/status/changelog and this report. No external JSON contract, SQL, provider boundary/parser, queue/routing, 8-second UI deadline, readiness, heartbeat, prefetch, pool, ACK/reject configuration, timeout, resources or isolation profile changes. Rollback is a source revert; there is no data migration.

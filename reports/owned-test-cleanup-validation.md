## Changes and retained boundaries

`browser_acceptance.py` adds four fixed stderr markers immediately before and after the existing HTTP-route and WebSocket-route awaits. Registration order, exceptions, absolute conversation deadline, navigation order and every sandbox/network/resource control stay unchanged.

`test_transport_acceptance.py` now wraps all held-response receipt/fairness/private-export assertions in `held_response_cleanup` inside the existing single-worker executor scope. `transport_cleanup.py` performs finally cleanup: exact `fixture-a` lookup, poison check, at most one fixed release exchange with the original shared five-second deadline and exact acknowledgement, followed by one future collection with the original 20-second timeout and synthetic-body marker assertion. It never sends on a poisoned fixture, resets poison, retries an uncertain exchange, touches a different fixture, changes a mode, or reconstructs topology. A separately poisoned gateway does not block the healthy fixture's Event release. Uncertain or wrong-ack exchanges poison the fixture. The receipt poller inspects an already-done future with `exception(timeout=0)`, preserving a stored failure or cancellation and the existing early-success assertion without calling `result()` outside cleanup. Existing gateway authorization and transport deadlines remain authoritative. A timed-out future can still have a live thread; this patch does not claim independent thread termination.

Original primary assertion/cancellation identity is re-raised. Secondary cleanup failures add at most two bounded, fixed stage/class notes without exception/guest text. With no primary error, cleanup errors fail the test. Success-path assertions still prove processing/export completion while the response is held. Release only sets the owned fixture Event, not a permission or admission state.
